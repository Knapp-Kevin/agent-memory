**boundaries**:
- limitations: the adapter decides; the host executes. An action's decision is an ordinary PAMA decision on a proposal whose operation is `action_execution`; the reference table gives it four cells and the authority-class floors are independent constraints that the ordinary action-evidence path cannot discharge. In this contract an executable allow therefore binds only for A0–A3 actions; A4 and A5 actions park with the floor's own requirement until a governance mechanism outside this path resolves it (not built here). A parked outcome binds nothing: the action cannot execute and no witness can be built for it. A witness attaches to any bound decision, allow or deny, and records what the host observed against it; it creates no authority. A bound execution authorization is single-consumption.
- non_goals: an external governance projection as the decision source (rejected at ideation; `provider_mode` stays `none` on this path); the mechanism that resolves an A4/A5 floor (a later sprint); a JS runtime port (Sprint 4b, held); a generic "pending authorization" object (R3); changing `commit_proposal`'s selection (#395); the DashClaw route (#392); reusable authorizations (the contract declares none).
- exclusions: `apply_action_governance`, `record_runtime_execution` and `ActionGovernanceDecision` keep their signatures and their two outcomes; `build_execution_witness`, `build_projection`, `compose`, `build_pama_decision` and `build_receipt` are called, not changed; the twelve existing memory operations' cells, both floors and every modifier are byte-unchanged; `evaluate_with_qualified_evidence` and `evaluate_with_external_verification` keep their discharge behaviour for memory operations (the non-discharge rule is enforced where the action path forwards, LD4); `reference/run_procedural_memory.py` and `test_procedural_memory.py`'s seam-level test keep manufacturing a decision because they exercise the seam, not the boundary; `runtime/adapter.py` gains no import from `memory` and no knowledge of actions (only a generic extension-state slot and three public accessors, LD4); no new dependency.

## Operator rulings this plan implements (2026-09-07)

- **R1**: `action_execution` is a new operation. `authority_change` is not reinterpreted: it changes the set or degree of authority an actor possesses; `action_execution` exercises authority already possessed to cause an externally meaningful action. The ADR records the distinction and states that `action_execution` is not a memory mutation merely because its decision or evidence is later recorded in memory.
- **R2**: minimum rows low `allow_with_ledger`, medium `require_review`, high `require_review`, critical `require_external_verification`; the authority-class floors stay independent (A4 lifts to at least `require_review`, A5 to `require_external_verification`); doctrine states the effective rule as the strictest of the operation/risk cell, the authority-class floor and every other applicable floor, over the PAMA outcome ordering.
- **R3 (as amended for C1)**: no `pending` at the seam. `allow`/`allow_with_ledger` bind an executable allow with the ledger obligation materialised first; `block` binds deny; `require_review`/`require_external_verification` bind nothing and surface the unresolved requirement separately; absence of a bound decision is fail-closed; **a witness requires a bound decision** (allow or deny), so a deny-bound execution is recorded as a violation and an unbound execution report is audit evidence, never a governed execution.
- **C7 ruling**: authority-class floors are independent governance constraints and are **not dischargeable** by R5 evidence or ordinary attestation on the action path. The decision preserves *why* an outcome exists as a set of active constraints (`risk_cell`, `authority_floor:A4_EXTERNAL_ACTION`, `authority_floor:A5_GOVERNANCE_CHANGE`, ...); the action path may bind allow only when no authority-floor constraint is active. The doctrine sentence is not weakened to "before discharge".
- **C6 ruling**: for every bound decision the adapter builds the canonical PAMA decision document, the receipt naming it, and the receipt event, **before** exposing the bound decision; any failure fails closed. Invariant: executable `allow_with_ledger` implies a resolvable `decision_ref` and a durable receipt.
- **Replay invariant**: a bound execution authorization is single-consumption; the seam consumes it, and the witness is bound to that consumption.
- **Iteration-5 rulings (2026-09-07, attempt-4 V1, C1-C3)**: the action-authority orchestration moves to a new `memory`-layer module that treats the runtime adapter as an injected collaborator; the dependency direction is `memory` action authority -> `runtime` adapter and never the reverse; the module is added to the package mover's table so the layout tests enforce its location rather than exempt it. **Restart invariant**: a successfully consumed action authorization remains consumed across supported runtime restart and restoration; restoration is fail-closed (persisted consumption state that is expected but cannot be restored coherently must not leave prior authorizations looking fresh); the persisted state is scoped to the identifiers that already define the authorization (`proposal_id`, `action_id`) and is not a universal replay ledger. **Known namespace limitation**: memory commits do not record proposal ids into the action-consumption namespace, so the same identifier may presently appear once in the memory path and once in the action path; uniqueness is enforced within the governed action path this sprint introduces, not globally across PAMA operations; global proposal/action identity coordination is future work. The amendment boundary is frozen to: relocate the orchestration; inject the adapter as collaborator; update the mover table; retarget the seam patch; persist and restore the consumption maps; document the cross-path limitation; preserve every previously approved behaviour and invariant unchanged. No doctrine change, no new authority semantics, no new outcome state, no redesign of the memory commit path.
